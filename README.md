# 会议转录 / Meeting Transcript

浏览器里的实时会议转录。麦克风和会议应用的声音分两路采集，本地模型转文字，
句子带说话时刻，结果留在本机，不上传任何服务器。

```
麦克风 ────────────┐
                   ├─▶ VAD 断句 ─▶ 16k WAV ─▶ 本地 ASR ─▶ 逐段显示
指定应用（窗口）──┘
```

- **我**：来自麦克风
- **对方**：来自你共享的那个应用/窗口

说话人靠**输入通道**区分，不靠声纹猜测，所以对方那边有几个人不区分。

## 前置条件

| 需要 | 说明 |
|---|---|
| macOS + Chrome / Chromium（Helium 等） | 共享音频依赖浏览器的屏幕/窗口共享能力 |
| [LazyTyper](https://lazytyper.com) 桌面版，保持运行 | 提供本地 ASR 模型（GGUF），本项目只调它的本地 HTTP 接口 |

本项目自身**零运行时依赖**：服务端只用 Python 标准库。

## 快速开始

```bash
git clone https://github.com/yinyu985/meeting-transcript.git
cd meeting-transcript
python3 server.py            # http://localhost:8787
```

打开页面，直接使用顶部两行音频输入开关：

1. **麦克风输入**：默认开启，记为「我」。
2. **指定应用输入**：打开后浏览器弹出共享框，选「窗口」和目标应用（腾讯会议、
   Zoom、浏览器标签页都行），并把音频共享打开。记为「对方」。

然后点主界面的「开始」。

必须是 `localhost` 或 `127.0.0.1`：`getUserMedia` 只在安全上下文可用。

## 两个输入是独立开关

| 操作 | 结果 |
|---|---|
| 录音中关掉某一路 | 立即停止该路采集，另一路继续 |
| 浏览器里点「停止共享」 | 应用那一路自动关闭，开关同步变灰 |
| 两路全关 | 点「开始」会提示先开一路 |
| 点主界面「停止」 | 释放所有采集流，下次需重新授权窗口共享 |

## 工作方式

### 断句（浏览器内）

`AudioWorklet` 把音频降到 16 kHz 单声道，每 20 ms 一块，主线程算 RMS：

- 阈值 = `max(0.006, 噪声底 × 2.5)`，噪声底在空闲帧上做 EMA，会适应房间
- 连续 3 帧超阈值判定开口，前 300 ms 缓存一起带上，不吃字头
- 录够 2 秒后，遇到 240 ms 停顿就提交；10 秒后改为 200 ms，20 秒后改为 160 ms，不再缩短
- 不足 2 秒的短句仍在静音 700 ms 后提交；通常最短 300 ms，手动停止时保留更短尾音
- 停顿门槛结合近期讲话峰值的 3%，最多为开口门槛的 2.5 倍，避免底噪让停顿一直被漏掉
- 停顿帧完整提交，不裁尾音；时长不直接触发切片，长时间没有检测到停顿时会延迟出字并增加内存占用

每段编码成 16-bit 单声道 WAV 发给 `/transcribe`。时间戳取「开口那一刻」，
不是模型返回那一刻，排队和冷启动不会让时间失真。

### 转写（本地）

`server.py` 把 WAV 转发给 LazyTyper 的 `/v1/audio/transcriptions`，端口从
`~/Library/Application Support/com.lazytyper.desktop/server.port` 每次现读，
App 重启换端口不用改配置。

**为什么需要这层代理**：LazyTyper 对带 `Origin` 头的请求返回
`403 Cross-origin requests are not allowed`，浏览器不能直连；转发必须发生在服务端。

### 切片与段落

两路独立处理，允许同时讲话，不假设交替发言。自动切片只在检测到停顿时触发，不按整秒硬切。
下一句用 300 ms 预录缓存保留起音。音频时间按采样数推进；手动停止时提交尚未结束的尾段。

显示段落与音频切片分离：同一路停顿不超过 1.8 秒时合并；另一方插话不会切断本方段落。
段落约每 60 秒在切片边界分开，避免无限增长。按段落开始时间排序，而不是按请求返回时间排序。
这是基于停顿的分段，不是语义断句；模型在切点处仍可能识别错误或多加标点。
不再跨通道删除相似文字，避免误删双方重复说的话。

### 性能观测与积压保护

两路采集和 VAD 同时运行。每路独立排队，同一路最多一个请求在途，保持文字顺序。
默认自动调度：待处理不超过两段时使用一个请求槽；达到三段时允许两路同时请求。
待处理包含当前请求。回落到两段时不取消在途请求，只暂缓发出下一段。
这一区分用于避免轻负载下争用模型资源，同时让积压时使用双请求吞吐。
这是本机 Lite 模型上的有限样本选择，不是对其他机器、模型或负载的最优保证。
每个请求测量音频时长、请求耗时及本地排队耗时。至少四次成功请求后统计 RTF，
并忽略观测窗口中的首个样本，降低冷启动影响。保留最近 16 次观测，不跨浏览器刷新保存。
RTF 不再改变切点；段落合并也不受识别耗时影响。
停顿规则和相对音量门槛仍是有限样本上的折中，不能保证最佳延迟或切点不出错。

状态栏显示待转写的**音频总时长**（含当前请求），不是预计等待时间。
积压达到两分钟时自动停止新增采集，并继续处理已录内容，停止瞬间的尾段也会入队。
积压清空前禁止重新开始。单次请求超过两分钟报错；失败不会阻塞后续队列。
浏览器中止请求不保证上游模型立即取消计算。失败音频当前没有自动重试或落盘恢复。

### 诊断日志

```bash
python3 -u server.py > /tmp/meeting-transcript.log 2>&1
```

服务端输出 JSON 日志：请求 ID、通道、音频开始时间、时长、切片原因、排队耗时、
处理耗时、状态和失败详情。不保存音频和成功返回的正文；错误详情可能包含上游信息，分享前请检查。
浏览器控制台同时输出切片事件。输入授权、音轨状态和会话起止也会记录；静音本身不触发告警。

## 界面

- 每段两行：人物 + 时间一行小字，正文另起一行
- 每段用交替的淡色底块区分，块间留 6 px；内边距上 7 / 左右 12 / 下 8 px，人物时间与正文相隔 3 px
- 容器始终居中，小 / 中 / 大三档上限为 560 / 820 / 1080 px。逐档实测，选能容纳三行的最窄档；大档仍放不下时自然增加行数，不再铺满宽屏。短句按内容收窄，小屏受可用宽度限制。字号、行距或窗口尺寸变化时重新测量；不裁字、不块内滚动
- 新句子追加在底部；不满一屏时贴底生长，满屏后自动跟随
- 底部两条独立音量条显示麦克风与应用的实际电平；停止后显示「待机」，未收到新音频帧时显示「无数据」
- 「复制」导出 `HH:MM:SS  我：正文`，可直接发给别人

顶部紧凑控制栏：麦克风与应用声音分两行，可独立开关。下方直接调整字号 15–32 px、
行距 1.0–2.25、「字幕渲染」着色开关，以及语言提示（自动 / 中文 / EN 单选分段按钮）。
不再使用设置抽屉。偏好存 `localStorage`，刷新保持。

点击「清空」后，按钮原位变成「确认清空」，下方出现「取消」。取消或按 Esc 撤销确认。

## 本地转写历史

主页点击「查看历史转录」，弹窗按时间倒序显示全部记录的开始时间、录音时长和非空片段数，不再隐藏第 200 条以前的记录。
点击「查看历史转录结果」查看正文，可复制全文或保存为 TXT，不会替换正在显示的实时字幕。

每次开始录音自动创建记录，每次成功转写由服务端写入 SQLite。停止录音后，排队结果仍归入原记录；
点「刷新」查看最新结果。时长是开始到停止的墙钟时间，不是有效讲话时长。
浏览器意外关闭时记录标为「未结束或异常中断」，不伪造准确结束时间。
清空主页字幕不会删除历史记录。详情顶部「删除记录」原位变为「确认删除」，下方可取消；删除不可在界面撤销。
正在本页录制的记录禁止删除。删除后，在途返回的转写不会恢复该记录；已导出的 TXT 文件不受影响。
删除是数据库逻辑删除操作，不承诺磁盘安全擦除；仅保留已删除记录的随机 ID 防止在途结果重新写入。

默认数据库路径：
`~/Library/Application Support/meeting-transcript/history.sqlite3`

可通过 `MEETING_HISTORY_DB` 环境变量指定路径。数据库不放在静态网页目录，也不提交到 Git。
历史没有自动过期规则，关闭浏览器、重启电脑和清理网站缓存都不会删除数据库。
但手动删除数据库、磁盘损坏、换机未迁移或切换数据库路径会导致记录丢失或不可见。
当前没有自动备份功能；重要记录请导出 TXT，并通过 Time Machine 等方式备份数据库。
历史只保存成功返回的文字和切片元数据，不保存音频。失败片段没有正文可供恢复。
首次启用需重启 `server.py` 并刷新页面；旧版浏览器缓存中的字幕不会自动导入历史，可先复制备份。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` `/app.js` `/recorder-worklet.js` | 页面 |
| GET | `/api/health` | `{"lazytyper":{"ok":true,"port":52718}}` |
| POST | `/transcribe` | 请求体是 WAV 字节 → `{"text":"..."}`，`X-Language` 头可选 |

## 已知限制

- **macOS 上浏览器不一定支持「只录某个应用」**。共享框里若写的是「系统音频」，
  其他应用的声音也可能一起进来；选窗口 + 打开音频共享通常最接近只录该应用，
  但这取决于浏览器实现，需要自己验证一次。
- **扬声器外放会造成重复**。对方声音从扬声器出来，麦克风也会拾到一份，
  于是同一句话会出现两次。戴耳机，或关掉麦克风那一路。
- **浏览器共享提示无法关闭**。「localhost is sharing a window and audio」是浏览器的
  安全提示，网页没有权限隐藏它。
- **整段进、整段出**，没有流式。出字延迟包含采集等待、本地排队和上游处理；没有通用固定倍率。
- 只转写，不做会议纪要总结。要总结需另接 LLM。
- LazyTyper 的 `auto_release_local_model_memory` 为 `true` 时，长时间空闲会卸载模型，
  下一次请求要等约 9 秒冷启动。
